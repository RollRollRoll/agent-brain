# ADR 0011: 根页面可以用已有页面，登记在本地文件里

**状态**：已接受（取代 ADR 0008）  
**日期**：2026-10-29  
**决策者**：用户

## 背景

ADR 0008 按根页面标题「LLM Wiki 系统」在 Notion 里搜索来定位 Wiki，所以 `/init-wiki` 只能新建一个这个标题的根页面。
用户希望把 Wiki 建在已有页面下，页面标题和原有内容不变。这样标题不再固定，按标题搜索就找不到了。

## 决策

- `/init-wiki` 运行时先问根页面用已有页面还是新建页面（用户在请求里说了就不问）。新建时可以给父页面和标题，
  标题默认仍是 `LLM Wiki 系统` / `LLM Wiki 系统（测试）`。
- 根页面登记在本地文件里，按页面 URL 定位，正式和测试 Wiki 各一条记录。登记文件有两个位置：
  - 项目登记文件：项目根目录的 `.agent-brain/wiki.json`，只对这个项目有效
  - 用户登记文件：`~/.agent-brain/wiki.json`，所有项目共用
- 定位时先找项目登记文件，没有这个 Wiki 的记录再找用户登记文件。init-wiki 登记时问用户写哪一个，推荐用户目录。
- 只有 init-wiki 写登记文件，其他 skill 只读。`.agent-brain/` 加入本仓库的 `.gitignore`，不提交。
- 两个文件都没有记录时直接停下，提示运行 `/init-wiki`，**不回退到按标题搜索**。
  已有的 Wiki 用 init-wiki 选「用已有页面」登记：根页面下 5 个数据库和 3 个分类页面都在时只登记，不改 Notion。
- 用已有页面时覆盖重建只移走 Wiki 结构（同名的数据库和分类页面），不移走用户的页面。

## 候选方案

- **A. 项目登记文件优先，没有再用用户登记文件（采纳）**
- **B. 改已有页面的标题为「LLM Wiki 系统」**：其他 skill 不用改，但会丢掉用户原来的标题。
- **C. 在根页面里写标记文字，按标记搜索**：`notion-search` 能否稳定搜到这段文字没有验证过。
- **D. 只用项目登记文件**：最初采纳的方案。`record-task` 由生成的 skill 在任意项目里调用，
  没登记的项目里任务都记不进 Agent Tasks，`analyze-failures` 和高频失败告警会缺数据，所以加上了用户登记文件。
- **E. 只用用户登记文件**：所有项目只能用同一个 Wiki，不能给某个项目单独指定。

## 后果

- 换机器要重新登记一次。这正是 ADR 0008 当初避免的问题，现在接受这个代价。
- 登记到用户目录后，任何项目里的命令和 `record-task` 都能找到 Wiki；项目自己登记的 Wiki 优先。
- 项目登记文件会遮住用户登记文件里的同一个 Wiki：项目里登记的根页面失效时直接报错，不会改用用户目录的那条，
  避免在用户不知道的情况下写进另一个 Wiki。
- 根页面的标题不再是契约，用户可以在 Notion 里随意改；页面被移入回收站或删掉时，各命令会提示登记已失效。
