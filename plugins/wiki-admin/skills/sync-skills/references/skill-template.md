# 生成的 SKILL.md 模板

`/wiki-admin:sync-skills` 按本文把一个 techniques 页面写成 SKILL.md。

## skill 名

- 由页面标题翻成英文：小写、单词之间用连字符、不超过 64 个字符，例如「LLM Wiki 入库」→ `llm-wiki-ingest`
- 不能和目标 plugin 里已有的 skill 重名；重名时在确认清单里提示，让用户改名
- 名字在第一次同步时由用户确认，写进 `sync-metadata.json` 的 `skill_path`，之后不再改

## 文件内容

```markdown
---
name: <skill 名>
description: <做什么>。<什么时候用：用户要做什么事、提到什么词时使用>。
---

# <页面标题>

<!-- 由 /wiki-admin:sync-skills 从 Notion 页面生成：<页面 URL>，同步时间 <ISO 时间>。
     要改内容请改 Notion 页面再同步；直接改本文件不会回写 Notion，Notion 页面再被修改时同步会提示人工合并。 -->

<一两句话说明这个方法解决什么问题，取自页面的「简短摘要」>

## 前置条件

- <页面「前置条件」的每一条>

## 所需工具

- <页面「所需工具」的每一条；没有这一节时，取前置条件里写明的软件、命令或服务>

## 步骤

1. <页面「步骤」的每一步，改成祈使句，主语是执行的 agent。页面标明由用户操作的步骤，写成「请用户……，完成后再继续」>

## 注意

- <页面「注意」「要点」中影响执行的条目；没有就删掉这一节>

## 失败处理

- <页面「失败处理」「常见问题」中的条目>
- 某一步失败时停下，告诉用户是哪一步、失败原因，不要跳过这一步继续

## 记录结果

开始第 1 步前记下开始时间。任务结束后，不论成功还是失败，先把结果告诉用户，再用 Skill 工具调用
`wiki-admin:record-task`，参数写明：任务名、使用的 Skill（`<plugin 名>:<skill 名>`）、开始和结束时间、
状态（成功 / 失败）、成功时的结果摘要，或失败时的失败步骤、错误信息原文和你对原因的分析。

- `wiki-admin:record-task` 不可用（没有安装 wiki-admin）或记录失败时，不影响任务结果，
  告诉用户「没能记录到 Agent Tasks」和原因即可，不要为了记录重新执行任务

## 出处

- Wiki 页面：<页面标题>（<页面 URL>）
- <页面「出处」一节的链接>
```

## 写法要求

- `description` 写给 Claude 判断何时加载这个 skill：先说做什么，再说什么情况下用。不超过 300 个字符，
  不写「这个 skill」之类的开头
- 「失败处理」一节总是保留（GLOSSARY「Skill」：包含步骤、前置条件、失败处理）。页面没有对应内容时，
  只写模板里那条固定的「停下并告诉用户」，不要编造具体的故障和解法
- 只改写，不扩写：页面没写的步骤、工具、条件不要补。页面写得不够执行时，这个页面不该被判为可执行（见 SKILL.md 判定标准）
- 页面里的 `<mention>` 换成被提及页面的标题；Notion 自动生成的 `http://<文件名>` 链接还原成反引号写法
- 页面里背景、原理、案例这类面向人阅读的内容不放进 skill（GLOSSARY「Skill」：面向 Agent 执行）
