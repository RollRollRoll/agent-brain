# record-task

agent 用 skill 执行完任务后，在 Agent Tasks 建一条记录（REQ-006，ADR 0003 阶段 1）。
**记录是附带的：记录失败不能改变任务结果，也不能让 agent 不把结果告诉用户。**

调用 `notion-*` 工具的前置条件、写入格式和报错处理见 [Notion 工具使用约定](../../references/notion-tools.md)。

## 输入

调用方在参数里给出下面几项，缺的从当前会话里补：

- **任务名**：用户请求的任务，一句话，例如「给 demo.mp4 做跳切」
- **使用的 Skill**：执行任务的 skill 全名，例如 `video-production:jump-cut`
- **开始时间**、**结束时间**：带时区的 ISO 时间，例如 `2026-10-23T14:05:00+08:00`
- **状态**：`成功` 或 `失败`。有任何一步失败、任务没有完成，就是失败。
  部分完成按失败记，在失败原因里写明完成了哪些步骤（ADR 0003 的修订说明）
- 成功时：**结果摘要**，产出了什么、放在哪里
- 失败时：**失败原因**，见下一节
- 可选：**Wiki**，根页面标题。没给时按 [定位 Wiki](../../references/locate-wiki.md) 判断；
  调用方或用户说了「测试 Wiki」就用测试根页面

本 skill 不重新执行任务，也不改任务结果。

## 失败原因的写法

依次写下面几段，每段一行开头标出名称：

1. **失败步骤**：skill 里第几步、做什么
2. **错误信息**：命令或工具返回的原文；有堆栈就附上，太长时保留开头和最后 20 行
3. **分析**：agent 认为的原因，归到 ADR 0003 的一类：工具路径/配置错误、前置条件缺失、输入数据格式问题、
   知识不足、外部服务不可用、Skill 逻辑错误；说明依据。判断不了就写「原因不明」和已经排除的可能
4. **建议**：要改 skill、改 Wiki 页面，还是用户补条件后重试

整段控制在 2000 字以内（Notion 单段文本的上限），超出时先删减错误原文，分析和建议不删。

## 步骤

1. **定位 Wiki**：按 [定位 Wiki](../../references/locate-wiki.md) 第 1–3 步找到根页面，取出 Agent Tasks 的 data source ID。
   第 4 步只核对 Agent Tasks：其他数据库或分类页面缺失时照常记录，不停下。
   这里有意偏离定位 Wiki 第 4 步的「缺了哪个就停下」：记录是附带的，Wiki 其他部分缺失不影响写入 Agent Tasks。
   Agent Tasks 本身缺失时按「失败处理」汇报。
2. **读取结构**：`notion-fetch` Agent Tasks 的 data source，确认字段名和「状态」的选项（成功、失败）。
   字段或选项对不上时不要改数据库结构，按「失败处理」汇报，并说明缺了什么。
3. **写入**：`notion-create-pages`，parent 用 data source ID，属性：
   - `任务名`：任务名
   - `使用的 Skill`：skill 全名
   - `date:执行时间:start`、`date:执行时间:end`：开始、结束时间；`date:执行时间:is_datetime` 为 1
   - `状态`：成功 / 失败
   - `结果摘要`：成功时写结果摘要；失败时写一句话说明没完成什么
   - `失败原因`：失败时按上一节写；成功时不填
   - `反馈/问题`：不填，留给用户和后续分析

   文件名照 Notion 工具使用约定用反引号包起来。
4. **回读**：`notion-fetch` 新记录，确认任务名、使用的 Skill、执行时间、状态都写对了，失败记录的失败原因不为空。
   不对时列出写错的字段、写入值和应有的值，问用户是否修正；用户同意后用 `notion-update-page` 的
   `update_properties` 改这一条，不要另建一条。用户不同意就保留原样，在汇报里写明哪些字段不对。

## 失败处理

工具报错（`rate_limited` 等）按 [Notion 工具使用约定](../../references/notion-tools.md) 处理（NEG-004），
其中「写到一半失败」指本节的汇报。

- `notion-*` 工具不可用、找不到 Wiki 或 Agent Tasks、字段对不上：不写入，按下面汇报
- 其他报错：不重试，按下面汇报

汇报时**照常把任务结果告诉用户**，再加一句「没能记录到 Agent Tasks：<原因>」，
并把本来要写入的各项列出来，用户可以手动补记，或稍后用 `/wiki-admin:record-task` 补记。
不要为了记录重新执行任务。

## 汇报

一行写清：已记录到 Agent Tasks（记录链接），状态是成功还是失败。
